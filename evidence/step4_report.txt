EXPERIMENTAL DESIGN
The methods ran in interleaved rounds. Each of the first four measured rounds
contained every method once, with each method occupying every position once
across those rounds. A fifth order was declared before execution. Exact order,
warm-ups, timestamps, all individual observations, and within-round speedup
ratios are retained in benchmark_summary.json. No run was excluded because
of its runtime. Quartiles use NumPy's linear interpolation convention.

The common primary interval covers input reads, graph construction where
applicable, coverage classification/counts, weighted normalized hazard, all
four GeoTIFF exports, closed/promoted files, and rereading the saved float32
normalized raster for index/classes. It includes actual computation. Setup,
cluster lifecycle, final validation, and independent comparisons are separate.
Files are closed at application level; forced physical-device fsync is absent.

Both methods use the frozen original rasters, mask, arithmetic, output grid,
NoData, class boundaries, DEFLATE compression, 256 x 256 TIFF tiles, and saved
float32 stage boundary. Baseline source is compiled from the pinned notebook;
Dask executes the unchanged 12-cell checkpoint source. Only declared settings,
output paths, suppressed interactive displays, and telemetry are supplied by
the runner. The Dask observer runs periodic callbacks without changing tasks;
its overhead is included in measurements. It buffers data in RAM and exports
it after primary timing.

CACHE, STORAGE, AND ENVIRONMENT
These are warm-cache workflow measurements: checksums and original component
validation read the input rasters before every timed calculation. A fresh
process does not flush OS caches. Inputs and output rasters are on the C: SATA
SSD. The frozen mask is on D: SATA HDD. Both methods retain the same original
mask for validation; Dask additionally reads its identical disk copy lazily
inside the primary interval. This preserves the previously declared comparison.
